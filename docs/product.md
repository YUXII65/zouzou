# 产品与 UI 规则（现行）

> 只写现在生效的规则；被推翻的版本见 [`decisions-log.md`](./decisions-log.md)。
> 写法：先说结论（祈使句），再补一句原因。

## 页面与导航

- 网页交互不要使用原生 `title` 属性生成悬浮提示，浏览器原生 tooltip 样式不可控且难看；语义信息放 `aria-label`，需要可见说明时使用自定义浮层。

- 全站只有三个页面：首页 `/`、文件 `/files`、个人 `/profile`。侧栏和移动端底部导航都只放这三项。
- `/tools`、`/workspace` 只是旧链接兜底（302 → `/files`），不算页面；全局命令面板也只列这三页 + 落地页预览 + 导出数据。
- 侧栏不放主题开关、不放账号头像；夜间模式、头像、昵称编辑全部收在个人页的名片里。原因：导航只负责导航。
- 新增整屏页面（没有应用外壳的落地页、登录页这类）必须同时加进 `src/lib/routes.ts` 的 `FULLSCREEN_ROUTES`。原因：这些页面用 `fixed inset-0` 覆盖，不进白名单就会透出 z-30 的侧栏和底部导航，落地页左上角会叠出两个 logo。
- 文件页和个人页的正文顶部不要再放「让想法，走成下一步 + 页面名」的标题区：`src/app/files/page.tsx`、`src/app/profile/page.tsx` 不渲染 `PageHeader`。原因：底部导航已经表明当前位置。
- `PageHeader` 组件仍供 admin / tools 等页面使用，不要为了「风格统一」把 slogan 标题加回文件页和个人页。

## 首页

- 快速记录是招牌入口：卡片与「今天要做」面板同宽（不要额外加 `max-w-3xl`，右侧不留空白），textarea 用 `rows={7}` + `min-h-44`，模式行用 `mt-2` 贴紧输入框。原因：不要做成又宽又高的巨框，也不要留半截空白。
- 提交按钮统一叫「下一步」；面板不再重复显示「今日推进伙伴」这类标题。
- 首屏不放日期面板、时钟、打卡统计：`src/components/current-time.tsx` 和 `src/components/calendar-date-panel.tsx` 目前没有挂载点，不要把它们接回首页。
- 固定 3 条演示示例，竖向排三行、一行一条。原因：并排网格或胶囊会把示例读成标签。
- 「今天要做」= 今天要推进的（最多 3 条，沿用 focus / 逾期 / 今日排期的排序）+ 今天完成的（`completedAt` 落在今天，最多 5 条，新的在前）。过 0 点自然过滤掉，不写定时清理任务。
- 「今天要做」右侧只显示条数，不显示「换一批」刷新按钮。
- 打卡模式开启后，「今日打卡」显示在「今日建议」上方；它按当天完成记录独立渲染，不占「今日建议」的 3 个推荐名额。
- 首页**不放**「XX 这一阶段完成了 / 下一阶段 →」这类阶段提醒卡：首页只回答「今天要推进什么」，阶段推进交给文件页。原因是这类提醒在不该出现的时候占掉了首屏。
- 澄清和最初输入必须长在同一张对话卡里：用户原话是气泡，AI 提问接在下面，不套额外边框或嵌套面板。原因：分成两块用户反馈「有点割裂」。
- 有待澄清时，整块快速记录表单（textarea + 下一步 + 示例 + 换一批）都不渲染，让位给澄清；示例只在 `pendingIds.length === 0` 时出现。
- 澄清区不留说明条和角标（没有「先确认一件事 / 只问会改变计划的问题 / 第 N 问」），不复述已确认的事实（不再推 `summaryText` 对话轮），也不渲染模型对上一轮的 reflection。
- 每轮只问新增的判断点，问题要短而具体，选项不能退化成「结果 / 限制 / 优先级」这类抽象分类。
- 澄清收口后自动生成任务，不显示「生成任务 / 计划编辑器」入口；完成态统一显示「已整理到文件，可以去看看。」，按钮统一叫「去看看」，两端文案一致。
- 澄清等待态要极简：只留「转圈 + 一行短文案」，不要进度条和两行说明；网页和小程序统一使用：首次输入「正在读你的话 / 正在理解你」，继续澄清「正在思考中 / 正在补充信息」，整理计划「正在确认情况 / 正在整理信息」。澄清框不要直接展示流式 JSON 的局部结果，最终问题和选项在完成时一次性替换。

## 任务与便利贴
- AI 输出的项目名、任务标题、`shortTitle`、`doneWhen`、`methodHint`、`recommendation`、`executionSteps`、线路名和用户行动卡，不能是字段名、示例标签或占位词（例如「项目标题」「任务标题」「完成标准」「线路名」「待补充」）。解析层要把占位词回退成真实内容，质检层要拦截；任何占位词都不能落库或显示给用户。

- 任务行外层显示 `shortTitle`（AI 理解动作、对象、场景后的重新概括），不能截取完整标题开头。点标题展开完整任务内容，不用悬停气泡。
- 点任务条的标题、来源、状态标签或下方空白都能展开便利贴；右侧操作按钮除外。
- 便利贴或文件夹因点外部而收起时，收起必须发生在这次点击自己的操作完成之后。用户可以一下点开另一个任务、另一个文件夹或推进任务状态，不能先只触发收起。
- 任务状态是一个按钮（`src/components/today-task-actions.tsx`）：待办 → 进行 → 完成，点一下往前走一步，字样和颜色跟着变。不要拆成三个并排按钮，不要显示状态徽章。
- 「完成」是终态：按钮 `disabled`、点击直接 `return`，不能再点回待办。点击后照常 `router.refresh()`，让分组和计数如实更新。
- 首页和文件页的任务条行为必须一致；任务展开区用 `useClickOutside`（点便利贴以外任意区域或按 Esc 就收回）。
- 不显示设置齿轮，任务展开区里也不放「编辑任务 / 删除」。
- 便利贴支持持久化多张叠放，单任务最多 10 张。
- 便利贴正文是执行卡片，不显示序号、标题、解释文字、「现在可以做」，不给单条删除按钮；不显示「补充信息」折叠块、`encouragement`、「调整依据」。要让必要的补充融进具体行动块本身。
- 步骤数最多 3 个真实动作：提示词要求 `executionSteps` 通常 2-3 条、最多 3 条，同一个动作的准备和执行合并成一条；`safePlanTask` / `stickyPayloadFromDecisionCard` 会把多余步骤并进最后一块。
- 便利贴里不追加「例外：…」这类 `fallback` 文字。fallback 照常生成、照常入库，只是不进便利贴。
- 步骤文本去掉 `1.` / `第一步` / `①` / `一、` 等前缀，界面上也不额外显示圆形数字；顺序由卡片排列表达。
- 便利贴底部只留一个输入框，占位文案「有卡顿？说说想法」；没生成过时给一个「生成便利贴」按钮，不要因为展开就自动调 AI。
- 计划编辑器（`src/components/inbox-plan-editor.tsx`）单条任务默认只露「标题 + 执行 / 优先级 / 截止日期」，其余字段收进「调整做法」`<details>`。原因：AI 已经定好的部分是默认值，不是待办事项。
- 首页「最近为什么调整」（`DecisionHistoryPanel`）暂不显示，组件保留在代码里。原因：用户说没看懂，想清楚怎么讲再放回来。
- 任务状态、便利贴建议、后续教练输出都走 `src/lib/decision.ts` 的同一套决策结构（推荐 / 理由 / 执行步骤 / fallback / nextStep / 完成信号），不要在各 action 或组件里各自拼字段。

## 文件页

- 一列文件夹，按模式分组；分组标题和文件夹副标题只用两个字：打卡 / 普通 / 长期 / 探索（不要写「打卡模式 / 普通模式 / 长期模式 / 探索模式」）。打卡固定在最上方，颜色用 `globals.css` 的 `--mode-*`，不要在组件里硬编码色号。
- 点文件夹就地展开，内容跟在它下面；默认全部收起（一个 `openId` 控制同时只展开一个）。只有从 `/files?project=<id>` 或 `?view=unassigned` 进来时才展开对应的那个。
- 展开后用 `useClickOutside` 收起（点卡片内部、点任务、点回看都不收起）。
- 提供「按类型 · 按时间」的小字切换（10px、无边框、右对齐），不做成大按钮条；没有文件夹时不显示。按类型 = 按 checkin / normal / longterm / explore 分组（默认，打卡置顶）；按时间 = 按 `project.updatedAt` 倒序平铺并显示各自模式。
- 不提供「新建文件夹」「放进一件事」「编辑文件夹」入口；新建只走首页 AI 流程，任务由 AI 拆。
- 不提供「删除文件夹」入口。
- 文件夹展开区的空状态分两种：**已经完成过任务、但当前没有推进中的任务**时显示「已全部完成」；只有确实一件都没做过时才显示「没有推进中的任务 / 写下想法时 AI 会把它拆成这里的任务。」
- 长期项目展开区只保留「还有 N 天」+ 阶段总结面板；探索项目展开区只保留线路图 + 任务列表。
- 长期项目阶段面板用「`1/5 阶段：小标题` / `2/5 阶段：小标题`」展示当前阶段和下一阶段，小标题写清这一步在把什么做成什么、接下来推进成什么样，不铺 deliverable / 里程碑原文。蓝色强调标在当前阶段行，下一阶段保持中性灰。
- 阶段预览面板**不铺下一阶段的任务清单**，只留一句话总结。原因：任务清单会把「预告」读成待办。
- 阶段预览面板**不出现「重新生成」**。下一阶段总结由服务端生成、页面自动补取，不要让用户手点。
- **「下一阶段」在当前阶段进行中就必须显现**，而且**不能让用户等模型**：计划确认后先预生成一次，任务状态变化时再补缺失；阶段收口时保留已有预览，不再清空重算。点「进入下一阶段」只做事务，不再卡在一次 5-7 秒的模型调用上。新阶段落地后，若后面还有阶段（`order + 1 < MAX_LONGTERM_STAGES`），再在响应之后预生成它的下一阶段；到上限不打无用的 AI。
- 万一首屏还没生成好，`stage-preview-panel.tsx` 会自动补取两次（3.5 秒间隔），不出现需要用户手点的按钮；待确认阶段在预览还没到位时显示「正在整理下一阶段」，不要误显示成「已收口」。
- 「进入下一阶段」只在阶段收尾（`status === "ready"`）且有下一阶段预览时出现；到阶段上限或没有新的真实里程碑时显示「当前阶段已收口，不再自动接下一阶段。」
- 探索线路图每行只显示「主线 / 支线 + 方向名」，不渲染 `intent` / `currentFocus` 小字（字段照常生成入库，只是 `file-browser.tsx` 不渲染）。探索项目不显示「当前练到哪」胶囊。
- 探索项目在计划确认后预生成下一条任务；用户完成任务时优先消费 `Task.nextTaskJson`，新任务当场出现，不能先显示空列表再等模型。预生成失败时才走响应后的补生成兜底。
- `/files?edit=<taskId>` 仍用来打开任务编辑面板（计划确认后的「去文件页」按钮走这里），不要指回 `/workspace`。

## 个人页

- 只有两块：名片 + 功能区。
- 名片 = 头像（点击即换）+ 昵称（铅笔改名）+ 普通 / 长期 / 探索三种 AI 模式的推进中数量（按 `Project.mode` 聚合）。打卡不在名片里计数。不显示灰色的 `@用户名`。原因：昵称和账号名相同时看着像重复。
- 头像不走对象存储：浏览器端用 canvas 压成 192×192 JPEG 的 data URL（约 10-30KB）存进 `users.avatarUrl`；服务端 `updateUserProfile` 只接受 `data:image/` 且 ≤400KB，否则丢弃。
- 功能区把「夜间模式」和「退出登录」做成同款按钮并排（`ThemeToggle variant="row"` 就是与退出登录同尺寸的按钮，不是整行开关）；不加大卡片、不加别的入口。
- 保留「API 连接」入口：服务端有 Key 时显示「服务端已连接」。不要把「没 Key / 超配额 / 超时 / 审计失败」混成同一个「AI 没接上」提示。
- 名片组件是 `src/components/profile-card.tsx` 的 `ProfileNameCard`；旧的 `ProfileCard` 下拉菜单已删除。
- 功能区由打卡模式、夜间模式、API 连接、退出登录四个同级按钮组成：竖屏 `2×2`，横屏一排四个。打卡未开启时打开手动填写面板，已开启时点击按钮进入取消确认。打卡不经过澄清或 AI 模式判定。
- 已开启时，打卡按钮右侧显示「✓ 第 N 天 · 编辑」，N 从创建当天算第 1 天，按上海时区切日；点击进入编辑内容，取消打卡放在编辑面板左下角，不能把编辑和删除做成同一个动作。
- 编辑打卡时可以改名、增删，至少保留一项、最多 30 项。保留的条目必须沿用原任务 ID，改名不能清掉当天完成记录。
- 打卡开启面板初始显示 3 条单行待办输入，底部只显示「＋」图标继续增加；点击后新增一条占位为「添加」的输入。任何已有内容的条目和新增条目右侧都显示「取消」，取消就是直接删除该行，不再自动补回空行。说明文案固定为「监督待办，培养习惯」。不要退回成一个多行 textarea。

## 打卡模式

- 每个账号最多一个打卡文件夹；数据库用 `Project.checkinOwnerId` 唯一约束兜底，不能靠前端只做一次存在性检查。
- 条目由用户在个人页逐行手动填写。开启后仍可从首页继续补充；同一个标题重复提交时跳过。
- 打卡条目是长期保留的模板，不每天复制任务。`TaskCheckinCompletion` 按 `taskId + checkinDate` 记录当天完成，`checkinDate` 固定用 `Asia/Shanghai` 的 `YYYY-MM-DD`；跨过 0 点查询新日期，状态自然归零。
- 打卡完成状态只影响当天派生视图，不写死 `Task.status`。因此同一条目次日仍可继续打卡，不会触发普通任务的「完成是终态」规则。
- 文件页的打卡文件夹用青色；展开后只显示当天清单和完成反馈，每条打卡是独立卡片。文件页不提供补充或删除入口；补充走首页，取消打卡走个人页按钮。
- 当天所有打卡条目完成后，在清单下方显示「今日打卡已完成，尽情探索你的边界吧」。

## 营销页与登录页

- `/landing`、`/login`、`/onboarding`、`/welcome`、`/guest/register` 完全不渲染侧栏和命令面板。
- 落地页演示保留 5 个不同处境（工具过载 / 关系沟通 / 创作选择 / 时间诊断 / 复杂活动），首次进入随机选一版；不展示场景标签。不要把演示收成单一故事。
- 「换一个演示」锚定在演示面板右下角（面板 `relative`，按钮 `absolute`），不能用 `fixed` 跟到视口右下角。小程序首页同理：`.refresh-demo` 放在 `.demo-panel` 内并保持 `absolute`。
- 演示支持左右滑动切换场景；首次进入显示低对比左右箭头 +「左右滑动切换」轻提示，用户交互后淡出。
- 自动播放中点击步骤暂停，暂停后点演示区域任意位置恢复播放。
- 演示输入用自然两行展示；计划页不显示「当前里程碑 / 这次先不做」；不加回「它是怎么运转的」「看 30 秒演示」。
- 登录页背景固定用 `src/components/halftone-spiral.tsx` 的蓝色半调螺旋，配色从主题变量 `--accent` / `--surface` 读取。不要加别的背景图或铺底渐变，也不要换成静态图片。
- 螺旋动态只能靠 CSS rotate（`@keyframes zouzou-spiral-drift`，周期 40s），纹理只在挂载时画一次。不要改回逐帧重绘 canvas（会回到 8-10% 单核占用）。
- 画布按视口放大并居中（`ZOOM = 1.45`），否则旋转到 45° 时四角会露出底色。
- 参数固定：`TWIST_A = 3.6`、`TWIST_B = -2.8`、`FREQ_A = 36`、`FREQ_B = 20`。
- 动画挂 `.zouzou-spiral-stage`；全局 `prefers-reduced-motion` 不能把这段背景动画直接关掉。
- 中心光晕（veil）半径取画布对角线的 0.575 倍，最外层颜色 stop 完全透明；`/login` 容器底色用 `bg-background`，不硬编码近似色。
- 页脚保留「走走 v3.5 · Coded by 氵」署名（`src/components/site-signature.tsx`）；用户已完成任务数 ≥ 3 时在署名旁显示「有改进意见？十分感谢！」，反馈写进 `usage_events` 的 `product_feedback` 事件，不新增数据库表。

## 注册、游客与新人引导

- 注册优先，游客是兜底：主 CTA 默认引导注册；创建游客账号前必须二次确认并说明「只在本机保存」。游客转正后回到应用，不重复跑 onboarding。
- 手机号验证完成前，落地页不显示游客体验入口；`GuestStartButton` 和游客流程留在代码里，只是暂不展示。
- 注册 / 登录是合并入口：账号存在就直接登录，不存在就用当前用户名和密码创建账号并进入欢迎页。
- 新用户引导由服务端 `first_run_tour` 驱动（`src/lib/first-run.ts`，判定 = 首启开关 +「注册 14 天内 + 项目 ≤ 1 + 任务 ≤ 3」），跨首页和文件页共 3 步：记录想法 → 任务下一步 → 便利贴。不要依赖 localStorage `next_step_new_user`；跳过大流程不能把引导一起关掉。
- 第 3 步文案固定：标题「使用便利贴」，正文「点一下【便利贴】，AI 会为你写一张详细执行步骤。你也可以补充自己的想法或卡点。」
- 引导气泡用 `createPortal` 挂到 body；任何「点外面就收起」的 document 级监听都要先忽略 `[data-floating-layer]`（`isInsideFloatingLayer`）。已知监听点：`src/lib/use-click-outside.ts`、`src/components/file-browser.tsx`。门禁：`scripts/verify-tour-dismiss.mjs`（需本地服务）。
- 游客态常驻可见：`GuestBanner` 说明「内容只保存在这台浏览器，注册后可长期保存」。游客账号是随机用户名 + 随机密码、从不展示，会话 30 天。
- 新手期任务行三个图标（拆成小步 / 设置 / 问 AI）通过 `showLabels` 展开文字，引导结束后自动收起。
- 注册、游客转正、跳过引导后都落 `/files`（`welcome/page.tsx` 的 redirect）。
- AI 设置入口只在个人页；`ai-settings.tsx` 必须在个人页保留，`ai-preferences.tsx` 保留但当前无挂载点。不要把 AI 设置加回首页。

## 数据与文案

- 项目归属默认新建：`ensureInboxProject` 只在调用方显式传 `reuseExistingProject: true`（计划的 `action === "existing_project"`）时才按项目名复用。原因：曾按名字无条件匹配，把「想制定年度计划」和「入坑某款游戏怎么玩」并进同一个项目。判断复用看「同一目标、同一对象、同一阶段」，拿不准就新建。
- 复盘保存时，后续任务要自动归入对应项目，不能继续堆进「未关联任务」。
- 复盘生成的下一步任务保留 1-3 条，每条两行：第一行精简标题，第二行具体说明。任务行显示精简标题，展开后显示完整内容；不显示序号或竖线。
- 不做 token / 成本看板，也不显示「今日 AI 用量 / 剩余次数」。AI 用量只作为后台配额与降级逻辑（`src/lib/ai-quota.ts`）；真要提示，只在快用完时给一行轻提醒。
- 界面少用解释性小字：页面标题下、步骤标题下、账号资料里的说明文案默认删掉。能用「写想法 / 谈感受 / 建项目 / 定今日」这类短标题表达，就不要补一句解释。
- 所有异步按钮和 AI 操作结束后必须可靠清除 loading / pending 状态；`SubmitButton` 在 pending 结束后主动 `router.refresh()`，pending 时保留明确文案和旋转状态，不再显示额外的小刷新按钮。

## 首页示例池

- 扩充流程：模型产出候选 → 用户 1-10 打分 → 归纳偏好。不要直接批量填充，也不要只看单条高分就复制它的措辞。
- 示例输入必须语义明确，避免「某个 / 一件事 / 一个方向 / 一个想法」这类没有对象的表达；不为了具体而堆数字、日期或虚构细节。
- 示例池不能让简单单步任务占多数，要优先体现走走的强项：多目标取舍、模糊想法澄清、卡点诊断、长期项目重启与持续推进、复盘修正、复杂约束协调。简单任务可以少量保留，但不能代表示例池质量。
- 候选要跨生活维度轮换（职业 / 项目 / 学习 / 身体 / 金钱 / 居住 / 旅行 / 友谊 / 家庭 / 身份 / 社区 / 数字生活 / 兴趣 / 纪念等），不能连续几批集中在同一类。多样性指真实困境与推进方式不同，不是只换名词。
- 后续批次按 5-6 个「卡点类型」分组、每类 2 条：价值冲突、停滞与重启、协作与控制权、注意力与数字生活、照护与责任、金钱与自我价值、结束与告别、复盘与判断、创作与审美、机会成本等。不要只按职业或生活题材换皮。
